# January 2016 daily offline extension

`case_2016_01.json` selects 2016-01-01–31 from the same frozen upstream-routed
7/5/3-unit reservoir-inlet data. Its first seven input days are byte-identical
to `inflows.csv`; the old seven-day assets and outputs are retained. Storage,
bounds and the provisional Prompton rating are shared without recalibration.

The baseline uses given pass-through release requests for FE Walter/Beltzville.
Prompton always uses the passive physical outlet. The two pulse response files
add FE +5 cms on January 4 and Beltzville +2 cms on January 15 separately.
`case_2016_01_delayed.json` applies an artificial one-day delay to the two
confluence-to-outlet edges; it is not calibrated river travel time.

Run each once with `scripts/run_llm_daily.py`, selecting its case and response
file, and a new output directory. For example, with the package installed:

```powershell
python scripts/run_llm_daily.py --case cases/fe_belt_prompton_offline/case_2016_01.json --responses cases/fe_belt_prompton_offline/responses_2016_01_baseline.json --output runs/month-baseline
python scripts/verify_offline_run.py runs/month-baseline
```

Repeat in separate new output directories using `responses_2016_01_fe_pulse.json`
or `responses_2016_01_belt_pulse.json`. For delay, use
`case_2016_01_delayed.json` with the baseline response file. No provider is
created. There is no automatic retry/resume; existing outputs are not overwritten.

[Source manifest](source_manifest_2016_01.json) retains original hashes and
93 selected source rows. [Results](../../results/three_reservoir_month_2016_01/RESULTS.md)
include all four saved traces and balance ledgers. The contribution-only,
approximate-rating, zero-loss, daily-mean initial-state and numerical-bound
limitations from [the original case](README.md) remain. Strategy audits are
UNKNOWN and live readiness remains false.
