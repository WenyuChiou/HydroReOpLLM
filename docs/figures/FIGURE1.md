# Framework figure: source and interpretation

The current figure uses the author's finalized v22 workflow with the HydroReOpLLM display-name revision. The native source is [hydrocnhs-coupling-framework-en.drawio](hydrocnhs-coupling-framework-en.drawio). Editable [SVG](hydrocnhs-coupling-framework-en.svg), [PNG](hydrocnhs-coupling-framework-en.png), and [PDF](hydrocnhs-coupling-framework-en.pdf) companions use the same diagram. The PNG is 4252 × 2617 pixels; the PDF is checked at 180 mm width. These are working export conventions, not verified journal requirements.

**Fig. 1. Structure and operational workflow of HydroReOpLLM.** Alternative rule-based and LLM-based agents submit release requests to shared reservoir calculations. Operating-rule check uses the date, inflow, and storage at the start of the day, together with the configured operating limits, to assess the release proposal. The check criteria are specified for each application. When enabled, the check completes before the physical update without automatically modifying or vetoing release. Decision records document the information supplied to the agent and its proposal, including model input and reply for LLM decisions. Execution records document implemented controlled release, spill, and the storage update. Trace records link these records and any check results; check and trace functions can also support rule-based agents. The Inflow branch to Available information represents the same inflow used by Reservoir operation; Release + spill is the implemented release and spill sent downstream. Requested release denotes the agent's proposal, and Storage supplies updated storage to the next decision step. Card colors indicate function: gray, information and its preparation; blue, physical calculations; orange, decision generation; and teal, checks and records. Pale frames indicate grouping; dashed card borders indicate optional components, although particular applications can require a check. Illustration colors have no additional categorical meaning. P, precipitation; T, temperature; PET, potential evapotranspiration; GWLF, Generalized Watershed Loading Functions; LLM, large language model. ABCD / GWLF denotes alternative rainfall–runoff models.


## Application boundary

The diagram describes the simulation interface. The saved LLM demonstrations replay a precomputed daily inflow series; they do not rerun rainfall–runoff at every decision. The package also supports the native stepwise interface. Each application must document its driver, information timing and routing checks. Operating-rule checks finish before physical implementation when enabled; their diagnostic FAIL/WARN/UNKNOWN results do not automatically change or veto a release. Runtime errors stop execution. Rule-based agents can also use checks and trace records.
